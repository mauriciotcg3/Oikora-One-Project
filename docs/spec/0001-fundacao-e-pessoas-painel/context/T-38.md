## 4. Decisões que se aplicam (só a decisão)
- **OIK-ADR-0003 §5** — origem: `docs/adr/0003-identidade-autenticacao-e-sessao.md:67-67`
  > 5. **Convite ao painel (BR-010, FLOW-005):** link de uso único com token aleatório guardado em hash, válido por 72h, revogável; enviado ao contato da Pessoa convidada. Quem já tem conta faz login para aceitar; quem não tem cria a conta e define a própria senha. Aceitar cria o acesso ligado àquela Pessoa — o vínculo vem do convite emitido pela organização, não de e-mail igual. Papel que exige 2FA obriga cadastrar o 2FA antes do primeiro acesso ao painel.
- **OIK-ADR-0003 §7** — origem: `docs/adr/0003-identidade-autenticacao-e-sessao.md:69-69`
  > 7. **2FA (BR-016):** código de 6 dígitos, válido por 10 min e de uso único, enviado por e-mail ou WhatsApp à escolha da pessoa; app autenticador (TOTP) disponível como opção e recomendado ao administrador; 10 códigos de recuperação de uso único gerados no cadastro do 2FA. Exigido a cada elevação para o painel quando o papel o obriga (administrador da denominação) ou quando a pessoa o ativou. Para quem tem 2FA obrigatório, o código não vai ao mesmo canal usado numa recuperação de senha nas últimas 24h. Operadores da plataforma usam TOTP obrigatório.
- **OIK-ADR-0003 §9** — origem: `docs/adr/0003-identidade-autenticacao-e-sessao.md:71-71`
  > 9. **Web (painel e área do membro):** Sanctum em modo SPA — sessão no servidor, cookie `HttpOnly`, `Secure`, `SameSite=Lax`, proteção CSRF; nenhum token acessível a JavaScript. Área do membro: sessão de 30 dias renovada com o uso. Painel: exige uma **elevação** própria (senha + 2FA quando aplicável) que expira após 2h sem uso ou 12h no total, sem derrubar a sessão de membro; rotas do painel conferem a elevação. Painel, área do membro e API ficam sob o mesmo domínio-pai (restrição registrada para o OIK-ADR-0011). Armazenamento da sessão (banco ou Redis) fica na Spec/OIK-ADR-0011, desde que permita listar e encerrar sessões por conta.
- **OIK-ADR-0003 §12** — origem: `docs/adr/0003-identidade-autenticacao-e-sessao.md:74-74`
  > 12. **Organização do contexto (OIK-ADR-0002):** com um único acesso ativo, a organização é automática; com mais de um, a pessoa escolhe num seletor após o login. A organização ativa fica **guardada no servidor** (na sessão web ou no registro do token do app) e, a cada requisição, é revalidada contra os acessos ativos da conta antes de gravar o contexto da RLS; nunca vem de parâmetro livre. Conta sem acesso ativo só chega às rotas da própria conta e de pedido de vínculo.

## 5. Rules aplicáveis (ID + frase)
Fonte: `.agents/rules/` da governança (localizar por ID; matriz em `.agents/rules/README.md`).
- **FE-GOV-001** — Identify the owning module, the API contract, and the operational impact before implementing a screen or flow.
- **FE-MOD-001** — A feature under `src/features/<Module>/` corresponds to the Laravel module `Modules/<Module>/` that owns the business rule shown on screen.
- **FE-MOD-003** — Code outside a feature imports exclusively from `features/<Module>/index.ts`.
- **FE-MOD-004** — Organize code in the owner feature and use only the segments (`api/`, `ui/`, `model/`, `lib/`, `types/`) the requirement needs.
- **FE-DEP-001** — Dependencies flow `shared → features → pages → app`.
- **FE-COMM-001** — Every call to the Laravel API goes through `shared/http/`. Do not instantiate an ad hoc HTTP client per component or feature.
- **FE-FLOW-001** — Components in `ui/` receive data and callbacks; they do not call `fetch`, axios, or an HTTP client directly.
- **FE-SEC-001** — Client-side validation and authorization are auxiliary; the backend always revalidates.
- **FE-TYPE-001** — `any` is forbidden. Exported function parameters and return types must be explicit; API contracts are typed from the approved spec.
- **FE-TEST-001** — A UI behavior change requires tests asserting what the user sees and can do, using React Testing Library.
- **FE-QUAL-001** — Run `tsc --noEmit` in strict mode and the configured lint before completion; do not suppress an error merely to pass the check.
- **FE-QUAL-003** — A frontend change does not integrate if it fails an applicable gate (types, architectural lint, tests).
- **FE-STATE-001** — Keep server state (API data, cache, invalidation, retry) and UI state (local selection, modal, filters) in separate abstractions.
- **FE-OBS-002** — Never log passwords, full tokens, cookies, or unnecessary PII.
- **CTX-001–011** — orçamento de contexto (sempre): uma task por sessão, Context Pack antes de documento, leitura dirigida, sem polling, saída enxuta.
