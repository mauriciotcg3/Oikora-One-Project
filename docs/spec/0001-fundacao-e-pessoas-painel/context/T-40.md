## 2. Critérios de aceite e regras
- **CA-11** (P FR-030; ADR-0004 §3) O administrador cria um papel com permissões do catálogo. O sistema recusa remover o último Administrador e recusa conceder permissão ou escopo que quem concede não tem. — `docs/spec/0001-fundacao-e-pessoas-painel/spec.md:158`
- **CA-12** (P FR-005; BR-013; ADR-0005 §2, §3) Cada ação administrativa, mudança de acesso e exportação gera uma linha de auditoria na mesma transação, sem valores de campo. Uma falha na gravação da auditoria desfaz a ação. O papel da aplicação não consegue `UPDATE`/`DELETE` em `auditoria`. Só quem tem `auditoria.ver` consulta. — `docs/spec/0001-fundacao-e-pessoas-painel/spec.md:159`

## 4. Decisões que se aplicam (só a decisão)
- **OIK-ADR-0004 §3** — origem: `docs/adr/0004-autorizacao-recurso-acao-escopo-e-dados-sensiveis.md:64-64`
  > 3. **Papéis prontos (BR-018).** Administrador: todas as permissões no escopo da organização. Secretaria: operação de Pessoas da sua igreja (§13) e as categorias sensíveis documentos, contatos e fé/conversão — saúde só se o administrador marcar. Ambos editáveis, com duas travas: sempre existe ao menos um acesso ativo com o papel Administrador no escopo da organização, e esse papel não perde `papeis.gerir`/`acessos.gerir`; **ninguém concede permissão ou escopo que não tem** (anti-escalada).
- **OIK-ADR-0005 §3** — origem: `docs/adr/0005-auditoria-historico-e-operacoes-desfaziveis.md:50-50`
  > 3. **Imutabilidade e leitura.** O papel da aplicação tem só `INSERT` e `SELECT` em `auditoria` (sem `UPDATE`/`DELETE`); tabela particionada por mês; a purga por retenção é `DROP` de partição feito pelo papel dono do schema num comando agendado. A leitura exige `auditoria.ver`, que vem só no papel Administrador pronto e respeita o alcance (OIK-ADR-0004); o suporte nunca lê a auditoria.
- **OIK-ADR-0006 §9** — origem: `docs/adr/0006-frontend-web.md:61-61`
  > 9. **Autorização na tela — o servidor decide, o cliente reflete.** Cada Resource de recurso editável devolve `meta.acoes` (ações permitidas sobre aquele registro, ex.: `editar`, `excluir`, `mesclar`) e, na área do membro, `meta.campos` com o modo de cada campo (`leitura`, `edicao_direta`, `edicao_aprovacao`; campo oculto não vem). Campo com aprovação mostra o valor pendente. `GET /me` devolve as capacidades que montam menus e a organização ativa. O cliente nunca deduz permissão por nome de papel nem esconde dado que o servidor enviou como forma de proteção; botão escondido é só conforto, o servidor revalida.

## 5. Rules aplicáveis (ID + frase)
Fonte: `.agents/rules/` da governança (localizar por ID; matriz em `.agents/rules/README.md`).
- **FE-GOV-001** — Identify the owning module, the API contract, and the operational impact before implementing a screen or flow.
- **FE-MOD-001** — A feature under `src/features/<Module>/` corresponds to the Laravel module `Modules/<Module>/` that owns the business rule shown on screen.
- **FE-MOD-003** — Code outside a feature imports exclusively from `features/<Module>/index.ts`.
- **FE-MOD-004** — Organize code in the owner feature and use only the segments (`api/`, `ui/`, `model/`, `lib/`, `types/`) the requirement needs.
- **FE-DEP-001** — Dependencies flow `shared → features → pages → app`.
- **FE-COMM-001** — Every call to the Laravel API goes through `shared/http/`. Do not instantiate an ad hoc HTTP client per component or feature.
- **FE-FLOW-001** — Components in `ui/` receive data and callbacks; they do not call `fetch`, axios, or an HTTP client directly.
- **FE-SEC-001** — Client-side validation and authorization are auxiliary; the backend always revalidates.
- **FE-TYPE-001** — `any` is forbidden. Exported function parameters and return types must be explicit; API contracts are typed from the approved spec.
- **FE-TEST-001** — A UI behavior change requires tests asserting what the user sees and can do, using React Testing Library.
- **FE-QUAL-001** — Run `tsc --noEmit` in strict mode and the configured lint before completion; do not suppress an error merely to pass the check.
- **FE-QUAL-003** — A frontend change does not integrate if it fails an applicable gate (types, architectural lint, tests).
- **FE-STATE-001** — Keep server state (API data, cache, invalidation, retry) and UI state (local selection, modal, filters) in separate abstractions.
- **CTX-001–011** — orçamento de contexto (sempre): uma task por sessão, Context Pack antes de documento, leitura dirigida, sem polling, saída enxuta.
